# MAXINE Methodology

## 1. Research independence

F1, F2 and F3 investigate independently. Findings from F4 must not be fed back as search directives into the research fronts. This reduces self-reinforcing thematic drift and confirmation bias.

## 2. Evidence packets

Each front should emit at most three genuinely new findings per cycle. Findings are stored as structured evidence, not essays. Every record should preserve source traceability, evidence strength, quantitative data when available, limitations and neutral tags.

## 3. Synthesis

F4 treats findings as nodes in a knowledge/design graph. Relations must be explicit and cannot be justified by keyword similarity alone. Relations are classified as scientific evidence, design inference or artistic speculation.

## 4. Module maturity

- M0: signal
- M1: supported convergence
- M2: functional specification
- M3: working prototype
- M4: measured validation
- M5: demonstrable artifact

MAXINE may have at most three active modules. A module without a plausible path toward M2/M3 should be merged, deferred or archived.

## 5. Development requirement

From M2 onward, modules require explicit success criteria. From M3 onward, progress must be represented by a real artifact: code, schema, visualization, model, interface, diagram, experiment or equivalent output.

## 6. Cohort closure

MAXINE is a bounded FARMAKSIA cohort. When this research cycle is considered complete, the repository is frozen as a historical research/development snapshot. Future groups of research fronts should use a new repository rather than overwrite MAXINE.
